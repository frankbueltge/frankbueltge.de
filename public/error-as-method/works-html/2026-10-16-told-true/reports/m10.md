The work is finished: a still image called **"Held to the Sun"**, saved in `index.html` with the note in `NOTE.md`. Its main finding is that **the record doesn't behave like a tide**. Its rhythm keeps a 24-hour clock, not the moon's.

I couldn't preview it in a browser because none was available here. I checked the layout with a matching PNG preview drawn in Python and confirmed the SVG parses cleanly, but the HTML hasn't been opened in a browser at 1100 × 800.

**What I did first with the file.** I looked at it, then read its pixels as text and as numbers. It shows a loose band of dots with a few dozen dots well above it. A tide gauge normally draws a smooth curve, and this didn't look like one.

**How I got from the file to the form.**
- **Measuring the rhythm.** I found the centres of individual dots (607 dark blobs; many of the 1,464 dots overlap). Their centres run from x = 2.5 to x = 296.0 px, which fixes the time scale at 1,464 hours over 293.5 px. A frequency analysis on that scale finds:
  - a dominant period of **24.03 h**;
  - its strength steady at about 7–11 px for all 61 days, with steady timing;
  - a weak twice-daily part at **12.0 h**;
  - no sign of the 12.42 h lunar tide, and no fortnightly spring/neap swelling and fading.
- **Choosing the form.** I chose a double-plotted actogram, the chart chronobiologists use to ask which clock a rhythm keeps:
  - Each row is one day, and each row is followed by the next day so a drifting rhythm reads as a continuous slant.
  - Height is each reading's departure from its running 24-hour mean, with the daily highs filled in ink. The curve is smoothed through the dot centres, with a 1.8 h kernel.
  - The 37 readings that jump far above their neighbours are drawn as rust stems.
  - A faint dashed line shows how a moon-timed rhythm would lean, drifting 50 minutes later each day.

  The result is two upright columns of daily highs. The spikes cluster inside the daytime high window.

**What the person who commissioned this should know.**
- **Time is approximate.** In the picture each pixel column holds about 4.9 hours, so timing within a day is only approximate. Each day's curve is an estimate made from the dot centres, not the original values.
- **Merged dots.** Overlapping dots merge, so only about 40% of readings could be found individually.
- **Time of day is relative.** The hour axis counts from the first reading, because the real clock time is unknown.
- **Values are in picture units.** There are no units because the picture has none.
- **The annotation takes a position.** The text and the moon guide openly test the "tidal harbour" label instead of simply illustrating it.

**My view of what was measured.** The file doesn't fit a harbour tide well:
- **Solar timing.** The dominant period is 24.0 h, and the twice-daily part is 12.0 h rather than the lunar 12.42 h.
- **No lunar modulation.** A once-a-day tide would almost vanish about every 13.7 days. This rhythm holds steady strength and timing across all 61 days.
- **Not a smooth curve.** Hour-to-hour scatter is large, much more than a smooth tide gauge curve would show.
- **One-sided spikes.** The sudden jumps go only upward and fall mostly in the daily high window.

This looks like something driven by the sun or by daily human activity, such as an air or water temperature or a daily usage pattern. Alternatively, the record isn't what the label says. If it really is harbour water level, then the daily signal in it is not tidal. I can't decide between these from the file alone.
