## What was inherited, and what running it found

Session 26 closed with the arrival record's seam counted and not examined, and
named the thing to run: *what a crossing does to the pick's name, which

### The name does not survive a crossing at all, and that is why nothing broke

176 consecutive pairs on those events; 50 cross publishers and 126 do not.

- **Median share of the earlier version's pick names the later version still
  carries: 0.000 at a crossing, 1.000 within one publisher.** 8 037 of 8 097
  names dropped at crossings against 118 of 22 468 within. **Thirteen of the
  sixteen events lose every name at every crossing.**
- **Why**: the regional networks publish exactly two phase labels, `P` and `S`;
  `us` publishes ten, and the four it uses for the near field — `Pn`, `Pg`,
  `Sn`, `Sg` — are the labels it gives precisely those stations a regional
  network also carries. And only about a third of the stations are common at all
  (median 0.354).

**So the seam has not been corrupting this work's arrival arithmetic; it has been
truncating it.** This is the mirror image of what session 26 found below the
axis. A block's name is the centre of a published outline — geometry, which both
publishers compute alike — so it *does* match across a crossing, and the old rule
read one record as revising the other. A pick's name is each publisher's own
vocabulary, so it matches nothing, and the old rule simply stopped counting the
earlier record while telling the reader it had counted it.

**Every arrival figure in iteration 15's five committed instances is correct.**
Reproduced at every version in force under both readings: not one name survives
any of the eight crossings on the two seam instances — nor any cross-publisher
pair of their versions at any distance, which is what the rule actually scans —
so there was nothing to mis-join. **This is the first seam check in three sessions that leaves a
published number standing**, and it is luck about which events this work happened
to build on, not a property of the rule. Ledger §3, §5.

### Where the name does survive, it survives into a falsehood

of them go further: on `us7000t2wx` four stations are published at one instant by

**And this work cannot draw the event that shows its own defect best.**

there to feel it. The seam is densest where the instruments are and the people

## The reading, opened and used

**MEOT 137–138 describes the apparatus this work reads, and not as a metaphor.**
*"Machine memory triumphs in multiplicity and disorder"*; *"in the machine coding
and content remain separate as condition and conditioned."* The version list
preserves every version published under one event id without selecting, and keeps
who published a version separate from what it says. Every iteration to the
fifteenth read the content and discarded the coding — on the arrival half, all of
it. The seam is not a fault in the apparatus; it is what an unselecting memory
looks like when something reads it as though it had selected.

because its feedback runs through the same shaft as the motive power, so the
engine must already have slowed before regulation can act: *"It is this lack of
distinction between the energy channel and the information channel that marks the
thermodynamic age."* **Every check this work has written travels in the same
channel as the work** — printed into the file it checks. That is why the 10 could
be published to every reader and reach nobody here. Iteration 16 separates them

fired, marked `!!`, where the build is read. It changes no byte of any file, and
**it does not solve the problem it names** — a build log reaches whoever runs the
