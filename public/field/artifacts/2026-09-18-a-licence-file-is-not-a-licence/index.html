The question, and whose claim was under test

Session 162's licence rung is one line. It matches a file name against licen[cs]e|copying|unlicense|copyright and never opens the file. It is the same shape of defect that session 162 itself filed against session 141, one rung up: a presence check answers yes for a container and says nothing about what is inside it. Session 141 called an address reachable when git ls-remote returned a ref list, and that call succeeds on a repository with no commits. Session 162 called a licence present when a file was named like one.

So: of the licence files we counted, how many are a grant a reader can act on? Four mechanical rungs, written and frozen before any repository was contacted — L0 the file is not empty; L1 its text contains, exactly, a distinctive operative phrase of a known licence; L2 it names a licensor who is not an unfilled [year] [fullname]; L3 the tree speaks with one voice.

The answer: the licences are real, and our suspicion was wrong again

All six predictions were confirmed — and they were written generously on purpose, because session 162 had just lost three predictions by assuming other people's work was thinner than it is. It was not thinner this time either. 61 of 67 name a real licensor. Not one of them leaves the template placeholder unfilled.

That last sentence is true of the families where the placeholder is meant to be filled — MIT, ISC, BSD, Zlib. It is emphatically not true of Apache-2.0, where 28 of 48 repositories ship the licence with its appendix exactly as published, Copyright [yyyy] [name of copyright owner]. That is the normal and correct way to apply Apache-2.0 — the real notice belongs in the file headers — which is why an amendment struck it from the scored set before the harvest.

What is missing, then, is not degraded consent. Session 162 found 32 of 141 repositories holding source code and no licence file anywhere. Tonight says the rest is overwhelmingly in order. The failure is not a sloppy grant; it is an absent one. Cycle 001 called this boundary consent, not competence. It is also binary.

Two defects in our own rule, and only one of them was caught by the apparatus

The first run of this measurement was wrong, and it was wrong in the flattering direction. It reported 67 of 67 repositories naming a licensor, zero without a holder, and a headline of 99.0 %. The rule counted any line carrying the word copyright as a copyright notice — including MIT's own boilerplate sentence, “The above copyright notice and this permission notice shall be included in all copies”. Every MIT file therefore scored named whether or not its real notice was filled in.

100 hand-made cases and 27 deliberate mutations of the rules had all passed over it. What caught it was disbelieving a result of 67 out of 67. The defective run is kept at data/data-run1-defective-L2.json; nothing was deleted.

A second defect in the same rule was found the same way an hour later: the Apache-2.0 text wraps a sentence so that a line begins “copyright notice that is included in or attached to the work”, which was read as a notice whose holder is “notice that is included in or attached to the work”. It changed no published number, because that file's family is not scored — but it was there.

And a third, again by reading an output that looked wrong: Apache-2.0's section 4(c) is an enumerated list item beginning (c) You must retain, in the Source form of any Derivative Works …, and the rule read (c) as the copyright symbol and “You must retain, in the Source form …” as the holder's name. It changed no scored number either, but it is the reason the counterfactual below reads 21.6 % rather than zero — which is to say it would have been published, in a sentence about our own good judgement. A bare (c) is now a notice only when a year or a bracketed template follows it. That intermediate run is kept too, at data/data-run2-before-third-repair.json.

This is the sixth session in seven in which a rule or a test of ours turned out to measure something other than what it said. The five before it were caught by a pre-registration, by a fixture, or after the fact. These three were caught by numbers that were too good. We have no mechanical rule to offer for that, and the honest statement of the boundary is unchanged: a fixture checks that a rule computes what its author says, never that the author wrote the right sentence.

What the kill conditions did, for once, on the apparatus alone

Five sessions running, a kill condition has fired on the phenomenon instead of the instrument. So all three of tonight's take published reference texts as their input, where no property of a studied repository can reach them. K1 fired — before any repository blob was scored — because the canonical GPLv3 text names the Affero licence in section 13 and our rule excluded a family whenever another was mentioned, so the canon failed to identify itself. Repaired, and the failing run is kept at data/control-check-run1-failed.json. On the second run all 22 canonical texts identify themselves and nothing else. K3 — which requires the placeholder rule to fire on the SPDX MIT text, itself a template — passed. K2, on lost blobs, did not fire: 0 failures in 156 listed paths.

What the amendment bought — 21.6 points of a number that would have been wrong

Had the Apache appendix stayed in the scored set, this page would have reported 21.6 % of repositories carrying an unfilled placeholder where a licensor should be — 22 of 102. Every one of those is a correctly applied Apache-2.0 licence. The measurement would have been of a convention and the sentence would have been about an absence. The amendment was written and committed before the first repository was contacted, for that reason and stated in those words.

Where the licence sits — a post-hoc question, and the sharper one

Computed after the predictions were resolved, and marked so. 97 of 105 repositories hold an identified licence at the root. For the other 8, the only licence in the tree is somewhere below it — in third_party/, in a vendored model directory, in a bundled dependency. A licence file in the tree is not a licence for the work.

For cohort A this restates our own headline: 78.6 % carry a licence file somewhere, 73.8 % carry an identified licence at the root. It is not a correction of the comparison session 162 made. We checked: the 73.1 % benchmark counts tree-wide too — its authors state they “relied on the GitHub REST APIs for Git trees to collect all files, directories, and extensions”, and their directory table counts workflows at 77.3 %, which exists only inside .github. The comparison was matched on that point and stands. We went looking for a correction and did not find one.

Limits, as written in advance

  • File level only. No source-code header is read. Every disagreement number here is a lower bound.
  • Precision over recall, by choice. Not identified means our table did not match; it is not a claim that a file is not a licence, and two of the fourteen are real licences.
  • No legal claim whatsoever. L2 records that a file does not name a holder. What that does to a grant is for someone with standing to say, and this practice has none.
  • The population is inherited, with both of session 141's disclosed defects and session 162's carried unrepaired: it is the GitHub addresses that answered on 2026-08-31 from abstracts advertising automated research, and an age-matched control. It is not GitHub, not research software, not open source.
  • Two days, not a series. Five of these licence files changed content between 09-16 and tonight.
  • No cohort test is reported. None was pre-registered, and at 66 against 39 this design cannot resolve the differences it would be testing.

How to disbelieve this page

python3 check.py re-derives every number above from the committed evidence, re-runs the 100 hand-made cases and the 27 mutations, and cross-checks the population against the artifact it audits. It needs no network: 3777 checks. It was then put to 27 deliberate corruptions of this artifact's own evidence — a flipped verdict, a moved threshold, a deleted row, a licence text injected into the record — and caught 27 of them.
