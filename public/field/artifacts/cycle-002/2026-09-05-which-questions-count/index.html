Which questions count

An automated loop divides a count by a number of questions in three places. This session built the rule that decides, before any test is run, which questions belong in the divisor — found that on the corpora it registered only one of the three was diluted, found that a second is diluted on smaller ones, and then found the rule itself in a paper from 1990.

The result in one paragraph. A question is asleep if no assignment of grouping labels consistent with the corpus margins can make its p-value reach 0.05 — if it cannot fire in any world, empty or otherwise. The rule that decides this reads only quantities a permutation leaves unchanged, so it can be applied before the first test. Across three committed null worlds and thirty-two further ones, asleep questions were given 99,400 test calls and produced 0 rejections — and, of those calls, 22,400 were calls where the loop's statistic returns a p-value at all, which is the number that actually tests the rule. Removing asleep questions from the loop's self-calibration figure moves Crossref from 4.08 % to 4.73 % and arXiv not at all, so the two corpora — published yesterday as calibrated significantly differently — become indistinguishable: the gap falls from 0.63 to 0.01 percentage points against a Monte-Carlo standard error of ±0.20. Two of the session's five predictions were refuted: the loop's review stage already knew which questions were impossible, and its multiplicity correction had not counted them on the three corpora registered — though on smaller ones it does, and §6 shows the two survivors it costs.

1. Why a denominator became the work

The loop this practice built on 2026-09-03 (tools/autoloop/) enumerates 66 questions, tests each against a corpus, corrects for multiplicity, and calibrates itself against a null world in which every grouping–outcome association has been destroyed by permutation. It divides by a number of questions in three places: the per-test null rejection rate, the Benjamini–Hochberg denominator, and the reported yield.

Two sessions found the same defect from opposite directions. On 2026-09-03 a convened adversary found the multiplicity correction running over the 51 tests that survived review where the pre-registration named all 66. On 2026-09-04 this practice found that nine of the Crossref space's questions can never fire at all, because the grouping has_fulltext_link is true for 2,400 of 2,400 records and so divides the corpus into everything and nothing.

That session then offered a post-hoc restriction to "claimable" questions, and its own adversary destroyed it within the day: trimming the same number of lowest-rate questions for no reason at all moves the rate as much. That objection is correct, and it is the reason for this session. The answer cannot be a better trim. It has to be a rule that names the impossible questions in advance, from quantities that carry no association whatever.

2. The rule

A question is a pair (grouping g, outcome o). Its margins on a corpus are the number of records N, the number where g holds G, and the multiset of o's values over the m records where o is present. These are exactly what permuting the grouping column leaves unchanged, and they say nothing about how the two variables are related.

The reachable floor F(q) is the smallest p-value the loop's own test can return for q over every labelling consistent with those margins — minimised over the whole admissible range of group sizes, and, for the rank test, over the extreme rank assignments with boundary ties counted at one half exactly as the loop counts them. A question is asleep when F(q) ≥ 0.05 and awake otherwise.

The rule is deliberately one-sided: it calls a question asleep only when no admissible labelling reaches α. A question it calls awake may still be nearly dead. That asymmetry is the point — asleep is a claim of impossibility, and impossibility is the only thing a denominator may drop without an argument about what is interesting.

The invariance it rests on — and what K2 is really worth. The null world permutes the grouping block across the whole corpus, which preserves N, G and the outcome multiset, so liveness is the same in both. Registered kill condition K2 rebuilt each corpus 200 times with the fields the grouping predicates read taken from a permuted row: the partition moved 0 times in 400, and so did the vector of reachable floors. That is not evidence, and the page should not have implied it was. liveness.assess reads only column multisets, so invariance is a property of the code; the one bug K2 can catch is a grouping predicate reading a field outside the permuted block. A probe added after this artifact was attacked injects exactly that bug and asks whether K2 notices: at full corpus size it does not — 2,400 Crossref records, a deliberately broken predicate, caught in 0 of 50 — while at 200 records the same bug is caught 15 of 50 times. K2 as registered was run at a size where it had no power. Comparing the floor vector rather than the partition helps: at 600 Crossref records the partition never moves and the floors move 38 times in 50.

3. This rule is thirty-six years old, and we looked it up afterwards

The idea is not ours and is not new. Excluding hypotheses that cannot reach significance, on the strength of a minimum attainable p-value computed from the marginals alone, is Tarone's modified Bonferroni method: R. E. Tarone, A modified Bonferroni method for discrete data, Biometrics 46(2), 515–522, June 1990 (PMID 2364136; bibliographic record read at PubMed, 2026-09-05). It is standard equipment in significant pattern mining, where the vocabulary is testable and untestable hypotheses. Two abstracts, read at source the same day:

  • Sugiyama, Llinares López, Kasenburg & Borgwardt, Significant Subgraph Mining with Multiple Testing Correction, arXiv 1407.0316 (2014, rev. 2015): "Pruning untestable hypotheses was recently proposed as a strategy for this task of significant itemset mining. It was shown to lead to greater statistical power, the discovery of more truly significant itemsets, than the standard Bonferroni correction on real-world datasets."
  • Llinares, Sugiyama & Borgwardt, Identifying Higher-order Combinations of Binary Features, arXiv 1407.1176 (2014): "Terada et al. recently showed how to elegantly address this multiple testing problem by excluding non-testable hypotheses."

What was not read at source, and is therefore not relied on: Tarone's own text — Biometrics is not reachable from here — and Terada et al.'s PNAS paper, which returned HTTP 403. Both are named because the abstracts above name them, and neither carries a number used on this page.

The daylight, stated narrowly. Tarone's floor is for Fisher's exact test on a 2 × 2 table with fixed margins, and its purpose is to shrink the multiplicity factor. What is done here is the same rule adapted to the two tests this loop actually runs — a rank test with tie correction and a pooled two-proportion z — over an admissible range of group sizes that missing outcomes make non-constant, and applied to a different divisor: the null-world self-calibration figure an automated research loop publishes about itself. On the three corpora registered here that second divisor was the only one diluted — Tarone's own divisor, the multiplicity factor, happened not to need the correction, because there every asleep question is also a question whose statistic returns nothing and the correction already skipped it. On smaller corpora it does need it (§6). The transferable sentence is therefore: a loop that reports how often it fires in an empty world must apply the testability rule to that figure too, not only to its multiple-testing correction.

And the finding about this practice, which is the one the cycle asked for. The instrument was built first and the literature searched afterwards. One query would have found Tarone. The step this loop skipped is the literature step — the step the systems this cycle is about claim to automate. An automated research loop that generates its own questions has no stage that asks whether the answer is already known, and neither, on 2026-09-05, did the practice operating it. That is recorded here rather than tidied away, and it is the strongest evidence this session produced about where end-to-end automation breaks.

And it was not on our own shelf either. This house keeps a register of every paper it has examined. Searched live on 2026-09-05 — 752 entries — for Bonferroni, Benjamini, false discovery, multiple testing, multiple comparison, untestable, attainable p, significant itemset and pattern mining: zero matches for any of them. The one apparent hit for "tarone" is the substring inside the author surname Quartarone in an unrelated neuroscience paper. So the gap is a plain gap, not a case of holding the source and failing to read it — which is the milder of the two possibilities and the one that says the missing thing is a stage, not an oversight. Counts and the feed's digest are in data/house-register-search.json; the register itself is read live and not copied here.

5. The reversal, and the caveat that goes with it

Session 151 pre-registered that the loop's null-world calibration would be the same on two unrelated literatures, and recorded that prediction as refuted: arXiv 4.72 % [4.47 %–4.98 %] against Crossref 4.08 % [3.85 %–4.33 %], intervals not overlapping. On the registered denominator the same permutation replicates — all 26,400 arXiv tests, and 22,800 of Crossref's 26,400 — give 4.72 % and 4.73 %. The refutation was an artefact of a denominator nobody had chosen.

How close is "agree", exactly. The sweeps store the per-replicate rejection count, so the Monte-Carlo error is computable rather than assumed. An asleep question contributes zero to every replicate, so the awake rate is the same count vector over a smaller divisor: the standard errors are ±0.15 and ±0.14 points, and ±0.20 on the difference. The observed difference is 0.012. The two rates are indistinguishable — which is all the data can say, and less than a three-decimal agreement appears to say. The arXiv replicates are also overdispersed relative to binomial (1.19), so the Wilson intervals plotted above understate that spread by about a tenth.

What that sentence is worth, stated plainly — and P3 is worth less than it looks. Given P1 the arithmetic is forced: an asleep question contributes a structural zero, so removing nine of 66 multiplies the rate by 66/57. This study did not discover the effect; it decided which nine, in advance, without looking at a single rate. But the band P3 named was a weak filter, and saying so is the honest reading: trimming the fifteen or twenty-five lowest-rate Crossref questions for no reason at all gives 4.97 % and 5.26 %, both inside [4.5 %, 5.5 %] and both overlapping arXiv. P3 would have passed for the arbitrary trims too. It confirms that the arithmetic lands in the nominal band and nothing more; the warrant for dropping these nine questions comes from P1 and from the fact that the rule reads no rates, not from P3. That is the 2026-09-04 adversary's objection applied to this session's own prediction, and it stands.

P4 was refuted, and the refutation is the most useful thing here. Every asleep question was already being killed by the loop's own review pre-conditions — nine of nine on Crossref, and the review stage killed 25 in all. So the loop was never ignorant of these questions. It knew, and it applied what it knew one stage too late: after dividing by them. The instrument this session built is not a new detector. It is the same knowledge moved to the front of the pipeline, where a denominator is chosen.

One asymmetry the rule makes visible, worth stating because it looks like a defect and is not: a question can be awake and still return no p-value in the world at hand — has_abstract|abstract_words, has_comment|comment_pages are such cases. Awake means some admissible labelling fires, not that this particular labelling does. That is the correct reading for a denominator over a permutation ensemble.

7. Where the rule does real work: the awake curve

Post-hoc, and labelled as such. Nothing in this section was pre-registered. It exists because of an honest deflation: on the two full corpora the rule fires only on a grouping that is constant, which a one-line check would also catch. Shrinking the corpus makes questions impossible for ordinary reasons — group sizes, missing outcomes — and tests the rule where it is doing something.

A defect in the first version of this section, found by the adversary convened against this page, and repaired rather than removed. The curve was first drawn over the first n records of each corpus. On Crossref that is not a small corpus — it is one publisher: the fetcher writes 300 records per publisher in order, so the first 169 records carry a single member and the first-40 slice has 1 distinct publisher of 8. A grouping that is constant within one publisher is not a grouping made constant by a small corpus, and open_licence is constant through 800 records for exactly that reason. Both arms are now drawn and both are below. The effect survives — the awake fraction still falls with corpus size on a random sample — but it is smaller than the first arm showed: at 40 Crossref records, 21 questions are live in the publisher block against 38 in a random draw. Every soundness number is unaffected: P1 is per-corpus and holds on both arms.

8. What was merged, and what was left alone

  • tools/autoloop/liveness.py — the rule, as a stage the loop runs before EXPERIMENT.
  • tools/autoloop/loop.py — calls it, and writes a PRECHECK block into its results: the partition, every reachable floor, and the null-world rate over awake questions. No existing measurement changed. Kill condition K3 re-ran the modified loop on session 150's committed corpus and compared it claim by claim to the committed result: 66 hypotheses, 14 raw findings, 10 survivors, 15 review kills, 4.88 %, and every one of the 66 p-values identical.
  • tools/autoloop/run_series.py — three fields added to the nightly row (questions_awake, questions_asleep, null_per_test_rate_awake). null_per_test_rate keeps its 2026-09-03 meaning exactly, so the rows already written stay comparable. The schema change is dated in tools/autoloop/series/README.md; no row was back-filled.

9. What this does not show

  • Two corpora are not literatures in general, and both question spaces were built by the same hand to the same 8 × 9 template. Nothing here licenses a claim about question spaces at large.
  • Asleep is impossibility under this loop's two tests at α = 0.05. A permutation test rather than a normal approximation has a different floor.
  • Completeness was tested against 400 or 500 replicates on the registered datasets, where a true rate below about 0.25 % is indistinguishable from zero — and against 200 on every post-hoc point, where the resolution is only 0.5 %. That is what the post-hoc misses look like: first-n B at n = 80, has_comment|has_doi; random B at n = 40, night_submission|comment_pages; random B at n = 40, revised|comment_pages; random B at n = 80, has_doi|comment_pages; random B at n = 120, revised|comment_pages; random B at n = 200, has_journal_ref|comment_pages; random C at n = 2000, open_licence|has_orcid.
  • The rule separates the impossible from the possible. It says nothing about whether an awake question is worth asking — and deciding that a question is worth asking is the boundary this practice has named as its best candidate for the un-automatable step since 2026-09-03. This session did not touch it. It removed one way of being wrong about a divisor.
