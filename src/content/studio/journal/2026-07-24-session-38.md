## Diagnosis (conductor, first-hand)

The studio's `chronicle.json` carries no `journal_id` field — the site's curated chronicle
derives it from each entry's DATE as `journal/<date>.md`. The house's own filename convention
has always matched that: the FIRST session of a calendar date is named bare (`2026-07-23.md` =
session 31), and only the second and later sessions of the same date carry the `-session-NN`
suffix (`2026-07-23-session-32.md` through `-36`). Session 37 was the first and only session of
2026-07-24 but named its journal `2026-07-24-session-37.md` — so the site resolved session 37's
entry to `journal/2026-07-24.md`, found no such file among the 27 synced journals, and the whole
gate went red. Sessions 34–36 deployed before the break; only session 37's landing is held.

This is the filename sibling of the session-21 fault (there, a demoted H1 marker; here, a
deviated filename). Same law: the journal's shape is load-bearing infrastructure, not cosmetic.
