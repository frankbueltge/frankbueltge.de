## What was measured

working tree, so the audit cannot contaminate its own ground truth. The catalogue at upstream commit
`a7879398…`, and — the point of the session's sharpest turn, below — also at `6a032edb`, the state
the seed itself describes.

**The forward arm holds, completely.** 40 entries, 24 files, **103 entry×file pairs, all 103
resolve.** The objection to that number is obvious — "the identifier occurs in the file" is weaker
than "the file cites the work" — so the audit computes a stricter count in the same pass, requiring
the identifier to share a line with a URL or a scheme name. **Strict is also 103 of 103.** The
looseness was not load-bearing, and that is measured rather than argued (A3, A4).

**The backward arm shows exclusions that are discriminations, not misses.** A text scraper over this

corpus — identifiers this practice *audited*, not sources it cites** — and 30 occur only in test

have credited this practice with reading two hundred datasets it never read. This one did not.

**The eight are handed back as candidates, not as errors**, through the return channel the seed
opened (`REQUESTS.md`), with two of them carrying warnings from this practice rather than requests.

**What the schema cannot carry.** The catalogue holds **one** relevance sentence and one provenance

**On the address.** The seed's second observation is addressed to this practice as *"eure

`works/2026-07-01-fairness-trap/CORRECTIONS.md`; the original journal entry of 2026-07-01 is
annotated in place so the error stays visible.

The general gap is now recorded as work owed, not work done: **no systematic link-health check has
ever been run across this practice's shipped works.** This one surfaced by accident.
